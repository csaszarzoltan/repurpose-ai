# RepurposeAI v1.5.0 Implementation Report

## Product understanding
Archive is valuable only when it is safely reversible. Before this increment, the backend retained archived projects but the main workspace made them effectively unreachable. v1.5.0 completes the archive lifecycle and adds mistake prevention.

## Improvements implemented
- Added `POST /api/v1/projects/{project_id}/restore`.
- Added an **Archived projects** workspace filter.
- Added **Restore project** on archived cards.
- Added confirmation before archive.
- Combined archived filtering with the existing project search query.
- Limited archived cards to view and restore actions.
- Preserved every generated variant and historical version across archive and restore.

## Architecture decisions
Restoration reuses the existing project update path and writes lifecycle status `draft`. It performs no variant mutation and requires no schema migration. The endpoint is idempotent when called for an already-active project. The browser continues to use the bounded list API with `include_archived=true` rather than introducing a parallel archive store.
