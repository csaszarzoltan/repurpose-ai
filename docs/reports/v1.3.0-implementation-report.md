# RepurposeAI v1.3.0 Implementation Report

## Product understanding
The repeated daily loop is not only create and review. Users also repeat successful project configurations and occasionally need to undo an editing direction. v1.3.0 reduces both forms of friction without introducing destructive update behavior.

## Implemented
- Added `POST /api/v1/projects/{project_id}/duplicate`.
- Added `POST /api/v1/projects/{project_id}/variants/{variant_id}/restore`.
- Added **Create similar** to project cards.
- Added **Restore this version** to each history entry.
- Added visible fallback-review attention count.
- Preserved source projects, prior variants, and approval history.

## Architecture decisions
Duplication creates a new `ProjectCreate` object through the existing repository path. It deliberately does not clone generated variants or lifecycle state. Restoration reuses the immutable version model and writes a new draft version with `history_restore` provenance rather than changing historical rows.
