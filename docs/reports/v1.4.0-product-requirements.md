# RepurposeAI v1.4.0 Product and UX Requirements

## Confirmed observations
- The project update API already supported editing source, formats, voice, guidance, and status.
- The workspace did not expose this behavior, forcing users to create a replacement project or leave the browser UI.
- Regenerating after a source correction is a normal repeated behavior, and existing variant history must remain available for comparison.

## Requirements implemented

### Must have
- **UR-140:** Users can edit an existing project's source and reusable generation settings from the project card.
- **UR-141:** Users can cancel editing without changing the saved project.
- **FR-140:** Project editing uses the existing owner-scoped PATCH endpoint.
- **FR-141:** Editing a project does not delete, rewrite, or reassign existing generated variants.
- **UX-140:** The create form clearly changes to an edit state with an `Update project` action and visible cancel control.
- **UX-141:** Entering edit mode preloads title, source, formats, voice, and guidance and moves focus to the form.
- **A11Y-140:** Edit and cancel controls are native keyboard-operable buttons, and status changes use the existing live regions.
- **REL-140:** Failed updates preserve all user input and existing server data.
- **SEC-140:** Editing retains existing production authentication and owner isolation.
- **TEST-140:** Acceptance tests prove UI discoverability and preservation of historical variants.

### Should have
- **UX-142:** Successful updates explain that existing draft history was preserved.
- **AN-140:** Existing content-free `project_updated` telemetry is reused rather than adding source content to analytics.
