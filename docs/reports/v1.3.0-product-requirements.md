# RepurposeAI v1.3.0 Product and UX Requirements

## Confirmed observations
- Users could inspect version history after v1.2.0, but could not restore an earlier version without manually copying its content.
- Repeated projects still required recreating source and settings or using a recipe that did not preserve source content.
- The attention API already calculated fallback drafts requiring review, but the workspace did not display that count.

## User-centered requirements

### Must have
- **UR-130:** A user can restore any historical variant as a new draft without overwriting subsequent versions.
- **UR-131:** A user can create a similar project from an existing project in one action.
- **FR-130:** Duplication copies source, formats, voice, and guidance but excludes variants and lifecycle/publication state.
- **FR-131:** Restoration creates a new sequential version with `draft` status and `history_restore` provenance.
- **UX-130:** Restore is available beside each historical version.
- **UX-131:** The workspace displays fallback drafts requiring explicit review.
- **SEC-130:** Duplicate and restore operations use the existing owner-scoped authorization policy.
- **REL-130:** Neither operation mutates the source project or historical variant.
- **TEST-130:** Acceptance tests prove isolation, non-destructive versioning, and UI discoverability.

### Should have
- **UX-132:** “Create similar” clearly communicates that drafts and publication state are not copied.
- **AN-130:** Duplication records only a content-free `project_created` telemetry event with source `duplicate`.
