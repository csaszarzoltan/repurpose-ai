# RepurposeAI v1.2.0 Product and UX Requirements

## Evidence summary

### Confirmed observations
- The v1.1.0 workspace already persisted projects, variants, and recipes and exposed non-destructive revisions.
- The project list had no search control despite a search-capable API.
- Users had no at-a-glance view of projects without generated drafts or variants still awaiting review.
- Unsaved create-form input was lost on navigation or browser refresh.
- Variant history existed in the API but was not visible in the workspace.

### Reasonable inferences
- Returning users primarily need to resume work, find a project, and identify content requiring review.
- Re-entering long source content after an accidental refresh is a high-cost failure.
- Version history is useful only if it is discoverable where editing occurs.

### Optional opportunities
Safe publishing previews, durable background jobs, encrypted connection persistence, visual workflow authoring, and real analytics remain larger follow-on increments.

## Requirements implemented

### Must have
- **UR-120:** Users can search saved projects from the workspace using title or source text.
- **UR-121:** Users can see active projects, projects needing generation, drafts awaiting review, and approved variants at a glance.
- **UR-122:** Unsaved create-form input is restored after an accidental refresh in the same browser.
- **FR-120:** The API returns owner-scoped attention counts based on active projects and each format's latest variant only.
- **UX-120:** Variant history is discoverable from every generated draft card.
- **A11Y-120:** Summary, search, autosave state, and history controls are labeled and keyboard operable.
- **SEC-120:** Attention counts use the existing owner/authentication policy and local autosave never enters product telemetry.
- **PERF-120:** Summary calculation is bounded and aggregated in SQLite without loading content bodies into application memory.
- **TEST-120:** Acceptance tests cover summary state changes and presence of critical workspace controls.

### Should have
- **REL-120:** Summary failure is non-blocking and does not prevent project creation or review.
- **UX-121:** Search can be submitted with Enter and cleared in one action.

## Acceptance criteria
- Summary counts exclude archived projects and superseded variant versions.
- Approving a draft updates latest draft and approved counts.
- Search uses the existing bounded project API with URL-encoded input.
- Local draft storage clears after successful save or explicit reset.
- No source, title, or generated content is sent through telemetry for autosave.
